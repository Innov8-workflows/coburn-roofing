## Deploying a change

```bash
cd "K:/AI/innov8 Workflows/Claude v2/coburn-roofing-site" && node build.js && node C:/Users/Jay/.claude/site-kit/engine/check.js
```

then

```bash
cd C:/Users/Jay/Projects/coburn-roofing && node sync.js && npx wrangler deploy
```

`check.js` runs in **client** mode here (`site.config.js` sets `mode: 'client'`),
which means no placeholders, a 2 MB payload budget and no base64 video.

## Things that will bite

- **`html_handling` is `"none"`, not the default.** The pages are flat
  (`services.html`, not `services/index.html`) and every canonical uses the
  `.html` form. The default `auto-trailing-slash` would 307 `/services.html` to
  `/services`, i.e. redirect every indexable URL away from its own canonical.
- **`_headers` is generated by `build.js`**, not stored here. Edit the generator.
- **The CSP lists the Apps Script hosts already**, before lead logging exists.
  If `connect-src` omits them the lead beacon fails silently and leads simply
  never arrive. Adding GA4 later means adding the Google hosts to `script-src`,
  `img-src` and `connect-src` too.
- **`workers_dev` is `false`.** Leaving it on publishes a second full copy of
  the site on a workers.dev hostname, competing with the real domain in search.
- Videos are served as real files from `_site/media/`. Do not inline them as
  base64: that is a house-rule hard failure for a client build, and it is what
  made the Stormproof hero take 49 seconds to become usable.
